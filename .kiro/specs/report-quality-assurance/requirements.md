# Requirements Document

## Introduction

This feature adds automated quality assurance capabilities to Primr, enabling users to validate and grade generated reports using a separate AI model. After spending 35-50 minutes generating a company intelligence brief, users need confidence that the output is accurate, complete, and ready for use before relying on it for strategic decisions.

## Glossary

- **QA System**: The automated quality assurance subsystem that evaluates generated reports
- **Primary Report**: The main company intelligence brief generated by Primr's research engines
- **QA Report**: The quality assessment output that grades and identifies issues in the Primary Report
- **QA Model**: The AI model used for quality assessment (separate from research generation models)
- **Quality Score**: Numerical rating (0-100) indicating overall report quality
- **Issue Classification**: Categorization of problems found (factual, logical, completeness, citation)

## Requirements

### Requirement 1

**User Story:** As a Primr user, I want automatic quality assurance on all generated reports, so that I can quickly see report quality and identify potential issues before using the analysis for strategic decisions.

#### Acceptance Criteria

1. WHEN a user generates any report, THE QA System SHALL automatically run quality assurance after report completion
2. WHEN the QA analysis completes, THE QA System SHALL display a clean summary showing "Grade: (XX/100)" in the CLI output
3. WHEN the QA analysis completes, THE QA System SHALL generate a detailed QA Report with identified issues saved to the workspace
4. WHEN the QA analysis fails due to API errors, THE QA System SHALL retry with exponential backoff and provide clear error messages
5. WHERE a user specifies `--no-qa` during report generation, THE QA System SHALL skip quality assurance

### Requirement 2

**User Story:** As a Primr user, I want comprehensive quality assessment of my reports, so that I can understand specific strengths and weaknesses in the analysis.

#### Acceptance Criteria

1. WHEN the QA System evaluates a report, THE QA System SHALL check citation accuracy and verify that referenced sources support the claims made
2. WHEN the QA System identifies logical inconsistencies, THE QA System SHALL flag contradictions and unsupported analytical leaps
3. WHEN the QA System assesses completeness, THE QA System SHALL identify missing sections or weak analysis areas based on the report template
4. WHEN the QA System evaluates factual accuracy, THE QA System SHALL flag claims that appear unsupported or potentially incorrect
5. WHEN the QA System completes analysis, THE QA System SHALL assign confidence scores to different sections of the report

### Requirement 3

**User Story:** As a Primr user, I want clean CLI output with detailed analysis available for review, so that I can quickly assess report quality without cluttering my workflow but still access comprehensive details when needed.

#### Acceptance Criteria

1. WHEN the QA System completes analysis, THE QA System SHALL display only "Grade: (XX/100)" in the main CLI output unless verbose mode is enabled
2. WHEN verbose mode is enabled, THE QA System SHALL display additional summary information including issue counts by category
3. WHEN the QA System presents findings, THE QA System SHALL save detailed analysis with specific line references and issue descriptions to a separate QA file
4. WHEN the QA Report is generated, THE QA System SHALL save it as a separate file alongside the original report for later review
5. WHERE the quality score is below 70, THE QA System SHALL add a warning indicator in the CLI output

### Requirement 4

**User Story:** As a Primr user, I want flexible QA model configuration, so that I can optimize for quality and cost based on my needs.

#### Acceptance Criteria

1. WHEN configuring the QA System, THE QA System SHALL support specifying a different AI model than the primary research models
2. WHEN no QA model is specified, THE QA System SHALL default to Gemini 2.0 Flash Pro for cost efficiency
3. WHERE a user configures Gemini 3.0 Pro, THE QA System SHALL use the higher-capability model for enhanced analysis
4. WHEN the QA System runs, THE QA System SHALL provide cost estimates for the quality assessment operation
5. WHERE QA model configuration is invalid, THE QA System SHALL validate settings and provide clear error messages

### Requirement 5

**User Story:** As a Primr user, I want QA integration with existing workflows and the ability to review detailed analysis, so that quality assurance fits seamlessly into my research process and I can access comprehensive details when needed.

#### Acceptance Criteria

1. WHEN using `primr doctor`, THE QA System SHALL verify QA model configuration and availability
2. WHEN the QA System completes analysis, THE QA System SHALL update the research workspace with QA results
3. WHEN listing reports with `primr list`, THE QA System SHALL indicate report grades and QA status
4. WHEN a user runs `primr qa "Company Name"`, THE QA System SHALL display the detailed QA analysis for the most recent report
5. WHERE multiple QA runs occur for the same report, THE QA System SHALL preserve QA history with timestamps
